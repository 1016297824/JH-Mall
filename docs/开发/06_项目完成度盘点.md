- **设计要求**（见 `docs/design/12_mall-order详细设计.md`）：

## 五、建议执行顺序（按依赖关系）

```
① mall-order 后端（含 OrderStateMachine + 下单编排）
   └─→ 打通「下单 → 锁库存 → 生成订单」主链路
② mall-marketing 后端（试算引擎被下单编排依赖）
   └─→ 补优惠试算，下单才能算钱
③ mall-payment 后端（依赖订单号）
   └─→ 打通支付 + 回调
④ 修复 mall-product 库存释放 + MQ 消费（订单取消链路闭环）
⑤ C 端前端：CheckoutPage → OrderList/Detail → Payment → Marketing
⑥ 补齐 mall-auth 缺失实现（IAuthService / IDecryptService / ISmsService）
```

**推荐从 ① mall-order 开始**：它是 payment、marketing 的前置，也是 C 端下单链路的核心缺口。

## 六、前端开发约定（必须遵守）

C 端前端开发**必须使用 `frontend-design` + `ui-ux-pro-max` 两个技能**，流程见 `docs/开发/02_前端技能调用流程.md`：

1. **设计系统（已完成，仅一次）**：`docs/ui-design/00_MASTER.md`
2. **每页三步循环**：
   - ① `frontend-design` 实现页面（严格遵循 `00_MASTER.md`）
   - ② `ui-ux-pro-max` 做 UX 检查 → 报告存 `docs/ui-design/[编号]_[页面名]_检查报告.md`
   - ③ `frontend-design` 按检查报告优化
3. **全局集成**：全部页面完成后用 `ui-ux-pro-max` 做全站 UX 审计
4. **编码规范**：`client/mall-ui/docs/CODING.md`
